# Конструктор DNS-записей

Веб-приложение для самостоятельного формирования DNS-записей почтового домена.
Все вычисления выполняются в браузере — приложение не обращается к внешним сервисам
и не хранит пользовательские данные.

Поддерживаются 11 типов записей:

| Тип | Назначение |
|-----|------------|
| `MX` | почтовый сервер |
| `A/AAAA` | IPv4 и IPv6-адрес (галочка добавляет вторую строку) |
| `SPF` | политика отправки почты |
| `DKIM` | подпись писем, генерация ключа RSA (2048 бит, legacy 1024) |
| `DMARC` | политика обработки несоответствий SPF/DKIM |
| `MTA-STS` | принудительный TLS |
| `TLS-RPT` | отчёты о доставке TLS |
| `SRV` | отдельные службы (IMAP, Submission и т. п.) |
| `CNAME` | каноническое имя |
| `BIMI` | брендирование в почтовом клиенте |
| `TXT` | произвольная текстовая запись |

## Требования

Для работы приложения:

- Windows
- .NET Framework 4.8
- IIS или IIS Express

Для запуска тестов дополнительно нужен **Node.js 18+**. Само приложение Node.js не требует.

- `npm test` — работает без установки зависимостей (чистая логика без браузера)
- `npm run test:all` — требует `npm install` и браузер Chromium
  (`npx playwright install chromium`)

Сторонние CSS- и JS-фреймворки в приложении не используются — jQuery, Bootstrap
и Modernizr удалены. Шрифт Montserrat лежит в репозитории, внешние запросы
при работе приложения не выполняются.

## Запуск

Откройте `DnsRecordGenerator.slnx` в Visual Studio и запустите проект (F5),
либо опубликуйте папку и откройте сайт в браузере.

Сборка из командной строки:

```
MSBuild.exe DnsRecordGenerator.slnx -t:Rebuild -p:Configuration=Release -p:MvcBuildViews=true
```

Флаг `MvcBuildViews=true` обязателен: он заставляет компилировать представления Razor
и ловить синтаксические ошибки в `.cshtml` на этапе сборки, а не в момент запроса.

## Тесты

Тесты лежат в папке `Tests` **вне** веб-проекта, поэтому не попадают в публикацию.

```
node Tests/run.js
```

Запуск без установки зависимостей выполняет базовые проверки: валидаторы,
генераторы записей, форматы вывода и корректность TXT по RFC 1035.

Чтобы дополнительно проверить поведение интерфейса в браузере, установите зависимости:

```
npm install
node Tests/run.js
```

Это добавляет проверки DOM через `jsdom` (перерисовка вкладок, валидация полей,
блокировка копирования при ошибке, раскрывающиеся блоки, устойчивость к мусорному
вводу) и проверки безопасности. Без `jsdom` эти проверки не пропускаются молча:
выводится явное сообщение.

Полный аудит в реальном браузере (требует Playwright и установленный Chromium):

```
npm run test:browser
```

Он сам собирает статическую версию представления, поднимает локальный сервер
и проверяет все 11 типов записей, выбор TTL, защиту от XSS и инъекций,
генерацию DKIM, маскирование приватного ключа и итоговой записи,
адаптивность и доступность. Всё вместе:

```
npm run test:all
```

Текущее состояние: **344 unit-проверок** и **80 браузерных**, все проходят.

### Непрерывная интеграция

`.github/workflows/ci.yml` запускает два набора задач при каждом пуше:
тесты и браузерный аудит на Ubuntu, сборка .NET на Windows с
`MvcBuildViews=true`. Статус виден во вкладке Actions на GitHub.

## Структура

```
DnsRecordGenerator.slnx            решение
package.json                       скрипты тестов (npm test / test:browser / test:all)
.github/workflows/ci.yml           непрерывная интеграция

DnsRecordGenerator/                веб-проект (ASP.NET MVC 5, .NET Framework 4.8)
  Controllers/HomeController.cs   два действия: Index и Error
  Views/Home/Index.cshtml         весь интерфейс
  Views/Shared/Error.cshtml       единая страница ошибки
  Scripts/validators.js          чистые функции проверки полей и санитизации
  Scripts/records.js             схемы и генераторы 11 типов записей
  Scripts/state.js               состояние приложения (домен, вкладка, значения)
  Scripts/app.js                  отрисовка, копирование, DKIM через WebCrypto
  Web.config                      заголовки безопасности и настройки приложения
  Content/css/site.css            оформление
  Content/fonts/                 Montserrat (три подмножества)

Tests/                            автономный тестовый набор без фреймворков
  validators.test.js records.test.js state.test.js   логика без браузера
  dom.test.js                     интерфейс через jsdom
  responsive.test.js security.test.js              адаптивность и защита
  browser-audit.js                реальный Chromium через Playwright
```

Логика разделена на независимые слои: `validators.js` ничего не знает об интерфейсе,
`records.js` не обращается к DOM, `state.js` хранит значения без привязки к разметке,
`app.js` отвечает только за взаимодействие.
Это позволяет тестировать генераторы записей и состояние без эмуляции браузера.

Общие переиспользуемые функции живут только в `validators.js`
(`escapeHtml`, `recordSafe`, `stripControlChars`) — локальных копий в других
модулях нет. Значения полей-списков подставляются в запись только через
защищённый выбор из объявленных вариантов, управляющие символы вырезаются
на уровне сборки записи.

## Формат вывода и TTL

Записи выводятся в формате зоны BIND: `имя TTL тип значение`.

```
@ 3600 MX 10 mail.example.com.
example.com. 3600 TXT "v=spf1 ip4:192.168.1.10 ~all"
mail.example.com. 86400 A 192.168.1.10
mail.example.com. 86400 AAAA 2001:db8::1
```

TTL выбирается один раз на общей странице и подставляется во все записи —
отдельно задавать его в каждом типе не нужно. Значение по умолчанию — 1 час
(3600). Для MX-записи имя выводится как `@`, потому что почтовая запись всегда
создаётся в корне домена.

Большинство панелей управления игнорируют TTL при вводе и подставляют своё
значение по умолчанию, поэтому поле сделано общим и необязательным настройкой.

## Принятые решения

**Строгая валидация вместо молчаливых исправлений.** URL и email отклоняются,
если содержат кавычки или обратные слэши: такие значения ломают строку TXT-записи
и «лечатся» только тем, что пользователь узнаёт об ошибке слишком поздно.

**TXT-сегментация по RFC 1035.** Кавычки и обратные слэши экранируются,
строка разбивается на сегменты длиной не более 255 байт **с учётом UTF-8** —
многобайтовый символ никогда не разрезается пополам.

**DKIM генерируется локально.** Пара ключей RSA (2048 бит по умолчанию,
1024 бит — для legacy-серверов) создаётся через WebCrypto в браузере.
Приватная часть доступна для скачивания и копирования и никогда не отправляется
на сервер. Генерация недоступна без HTTPS и без `crypto.subtle` — это ограничение
браузера, а не проекта.

**IDN-домены конвертируются на входе.** Кириллический домен (например, `пример.бел`)
преобразуется в punycode через встроенный парсер URL при вводе, и в записи всегда
идёт только ASCII-форма — DNS не понимает Unicode. Одиночные поддомены и селекторы
остаются строго ASCII: там невидимые символы и омоглифы почти всегда означают
ошибку ввода или подмену.

**Безопасная конфигурация по умолчанию.** В базовом `Web.config` стоит
`debug="true"` — это сделано для удобства разработки. Значения для публикации
выставляют трансформации: `Web.Release.config` переключает `debug` в `false`
и `customErrors` в `On`, `Web.Debug.config` — обратно. Поэтому публиковать
нужно конфигурацией **Release**: при публикации в Debug на сайт попадёт
отладочный режим и подробные тексты ошибок.

**Защита от инъекции DNS-записей.** Перевод строки в значении позволил бы
дописать в запись дополнительные строки при вставке в панель управления.
Поэтому управляющие символы отвергаются валидаторами и дополнительно
вырезаются на уровне сборки записи. Значения полей-списков подставляются
только из объявленных вариантов — подстановка извне игнорируется.

**Приватный ключ скрывается.** После генерации и показа DKIM-ключ маскируется
через минуту, а после копирования выводится напоминание, что ключ нельзя
передавать посторонним.

**Страница ошибки существует.** `customErrors` перенаправляет на `~/Home/Error`,
поэтому в контроллере есть соответствующее действие, а `Error.cshtml` не зависит
от `_Layout` и остаётся работоспособной при любой ошибке.

## Что нужно учесть при развёртывании

- Приложение использует `crypto.subtle`, поэтому генерация DKIM-ключа требует
  HTTPS (для `localhost` браузеры делают исключение).
- `packages/` содержит NuGet-пакеты и **отслеживается git** (318 файлов в истории),
  хотя `.gitignore` его исключает для будущих добавлений. На чистой машине
  выполните `nuget restore DnsRecordGenerator.slnx`.
- Публикуйте конфигурацией **Release** — см. «Принятые решения» выше.
- `MvcBuildViews=true` стоит включать и в CI: без неё сборка не проверит `.cshtml`.

### Чек-лист безопасности развёртывания

Защита от clickjacking и подмены типов содержимого — это заголовки сервера,
а не код страницы. Проверьте, что в продакшене отдаются заголовки из
`DnsRecordGenerator/Web.config` (`X-Frame-Options: DENY`, `X-Content-Type-Options`,
`Referrer-Policy`, `Permissions-Policy`, `COOP`, `CORP`, HSTS):

```
curl -sI https://ваш-домен/ | grep -iE "x-frame-options|x-content-type|referrer|cross-origin|strict-transport"
```

Если сайт стоит за обратным прокси, заголовки должен добавлять прокси —
`Web.config` IIS за ним не сработает.

## Известные ограничения

- SPF принимает IPv4 (`ip4:`) и IPv6 (`ip6:`). Голый IPv6-адрес без префикса
  распознаётся автоматически.
- Кириллический домен преобразуется в punycode автоматически при вводе —
  в записи всегда идёт только ASCII-форма. Одиночные поддомены и селекторы
  остаются строго ASCII: там невидимые символы и омоглифы почти всегда
  ошибка, а настоящий IDN-кейс закрыт полем домена.
- Браузерный аудит (`npm run test:browser`) проверяет Chromium. Поведение
  WebCrypto и буфера обмена в Firefox/Safari покрыто запасным механизмом
  копирования, но глазами не проверялось.
